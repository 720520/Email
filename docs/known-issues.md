# 已知问题

## BUG-20260807-001：报表净值和收益指标未完整考虑分红复权

- 状态：已确认，待修复
- 优先级：P1
- 影响模块：报表中心、PPTX 净值曲线、区间收益、年化收益、夏普比率和最大回撤
- 确认日期：2026-08-07

### 问题表现

1. 净值曲线直接使用托管表格的累计净值，但没有独立的分红事件和复权总回报指数。
2. 区间收益当前按“期末累计净值 / 期初累计净值 - 1”计算。期初已包含历史分红时，该口径不等于区间总回报。
3. 同一基金存在总份额、A/B/C 类时，报表默认选总份额；前端尚未提供明确的份额选择器，可能与用户预期份额不一致。
4. 历史净值不完整时，系统仍以数据库第一个可用点计算“成立以来”指标，可能产生误导性结果。

### 当前实现证据

- `backend/app/services/reporting_service.py::_nav_series()` 优先选择总份额，并在累计净值缺失时回退到单位净值。
- `backend/app/services/reporting_service.py::_performance_metrics()` 直接将累计净值序列用于所有收益与回撤计算。
- `backend/app/services/report_presentation_service.py` 将同一累计净值序列写入内置模板和上传模板的图表。

### 根因

当前数据模型只保存单位净值和累计净值，没有分红事件、除息日、每份分红金额和复权方式。报表服务因此无法区分“原始净值展示”和“可比总回报计算”。

### 临时风险控制

- 对外发送前人工核对报表份额类别、最新单位净值和累计净值。
- 已发生分红或历史数据不全的产品，暂不直接使用系统计算的成立以来、年化、夏普和最大回撤指标。
- 净值与收益指标仍不提供人工改写入口，避免绕过原始来源和审计链。

### 修复方案

1. 新增租户隔离的 `fund_distribution` 分红事件表，记录主产品、份额代码、除息日、派息日、每份分红和来源附件。
2. 从分红公告、托管邮件和附件提取分红事件；人工修正必须填写原因并写入审计日志。
3. 将每日总回报因子定义为 `(当日单位净值 + 当日每份分红) / 前一净值日单位净值`，连乘生成从 `1.0000` 开始的复权总回报指数。
4. 报表中同时保留最新单位净值、累计净值和复权曲线，不混用概念。
5. 报表配置页必须明确选择份额类别；报表快照保存最终份额代码。
6. 历史数据未覆盖成立日时，禁止输出成立以来、年化和全历史回撤，改为“历史数据不足”。

### 验收标准

- 无分红、一次分红、多次分红、A/B/C 份额和分红缺失五类测试数据均有单元测试。
- 复权指数、区间收益、年化收益、夏普和最大回撤与经人工复核的标准样本一致。
- 份额选择、分红来源、人工修正及报表输入快照可在审计日志中追溯。
- 历史数据不足时不生成伪精确指标。
