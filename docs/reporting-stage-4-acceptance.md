# 报表平台阶段 4 验收记录

## 已完成闭环

- `ReportBatch` / `ReportBatchItem` 保存批次、单项状态、冻结快照、幂等键和抢占信息。
- Web API 只创建、查询、重试、取消和打包，不执行批量 PPTX 渲染。
- 独立 Python Worker 默认 2 并发，使用条件更新原子抢占，并可回收超时的 `processing` 任务。
- 单项失败隔离，重试复用原 `ReportRun`，不重复创建生成记录。
- 前端支持产品多选、进度、成败数量、单项错误、重试、取消和 ZIP 下载。
- Linux 一键启动器会同时启动和停止批量报表 Worker。

## 自动化验收

- 1、10、100 个基金：验证批次创建、队列消费、状态汇总和运行记录数。
- 故障隔离：中间一项模拟失败，其他项仍成功；重试后原 `ReportRun` 被复用。
- 并发与恢复：两个 Worker 领取不同任务，超时锁可回收。
- 安全：其他租户作用域不能读取批次及单项。
- 真实渲染：内置模板生成的 PPTX 可重新打开，ZIP 同时包含成功文件和 UTF-8 失败清单。

## 本机基线（2026-08-21）

- 1/10/100 项队列编排、快照和状态测试合计约 2.2 秒。
- 单份真实 PPTX 渲染、取消及 ZIP 闭环在同一测试套件中通过。
- 全量后端 122 项测试在约 10.8 秒完成；前端 13 项测试通过。

注：100 项基线主要测量队列、快照和状态开销，避免 CI 重复执行 100 次高成本图形渲染。
生产上线前应在目标机型上用真实模板补录单份平均时间、10/100 份总耗时、
峰值内存、失败率和 ZIP 时间。
